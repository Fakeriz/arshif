## 2. Security Posture Summary

This full-repository `standard` audit covered all **20 security coverage units** across Arshif's Expo/React Native client (Web, Android, iOS + custom Expo native modules for SmartLog notifications and document scanning), 18 Supabase Edge Functions, 33 Postgres SQL migrations, Storage buckets, pg_cron schedules, and Vercel/EAS deployment configurations.

- **Confirmed Vulnerabilities:** **0** (all unrefuted source-grounded paths require dynamic execution and/or owner observation of external deployment state before confirmation).
- **Independently Verified Leads (`needs_validation`):** **25** distinct root-cause records across authentication/OAuth, Postgres RLS triggers & RPCs, billing webhooks & entitlement sync, external proxies & AI ingestion quotas, account deletion/backup/SmartLog local state isolation, and native WebView/supply-chain/OTA release controls.
- **Refuted Candidates (`rejected`):** **1** claim disproven directly against installed native SDK sources (detailed solely under Coverage & Refutation Notes below).
- **Hardening Observations:** **26** deduplicated defense-in-depth improvements (from 51 raw Wave 1 + Wave 2 notes).

High-signal systemic themes warranting prioritized owner verification in [NEEDS-VALIDATION.md](./NEEDS-VALIDATION.md) include: (1) Postgres multi-tenant trigger ordering & DoS amplification (`debt_payments_apply` running before `debt_payments_refs` and before `ON CONFLICT DO NOTHING`, unvalidated `profiles.notif_prefs` aborting shared `planning_reminders` cron, and `restore_rows` bypassing statement-level balance triggers across 500 subtransactions); (2) Edge Function quota/DoS boundaries (post-inference `quota_refund` on 422/502, `symbol-search`/`entitlement-sync` per-isolate rate limits, unbounded `asset_price_keys()`, 5x–6x isolate heap expansion on ingestion); (3) Billing & webhook state machines (grant/refund races across Edge Workers, pre-lock `refund_shift` read, out-of-order refunds acked and dropped, Xendit `null` amount coerced to `0`, and sandbox payment env drift); (4) Auth & client state isolation (implicit `arshif://` OAuth & static state fallback, sign-out stale async reload leakage, SmartLog `CaptureStore`/`HELD_KEY` logout races, incomplete account deletion storage cleanup & persistent Drive/recovery keys, and unrevoked recovery/suspended sessions); and (5) Client/release containment (TradingView `srcDoc` `allow-same-origin`, un-allowlisted native WebView `Linking.openURL`, unpinned third-party runtime scripts without SRI/script-src CSP, and `expo-updates` enabled without code signing).

### Refuted Candidates (Excluded from Findings)

- **`ios-backup/supabase-session-asyncstorage-unexcluded`** (*`rejected`* — not a vulnerability): Supabase Auth session tokens persisted in AsyncStorage lack iOS backup exclusion despite Android-only data extraction rules. Refuted in source because Direct inspection of the installed native dependency sources in node_modules refutes both the claim and the asserted validation blockers. In @react-native-async-storage/async-storage v2.2.0 (node_modules/@react-native-async-storage/async-storage/ios/RNCAsyncStorage.mm:518-527), omitting RCTAsyncStorageExcludeFromBackup from Info.plist (app.json ios.infoPlist is {}) causes RNCAsyncStorage to default isExcludedFromBackup to @YES and set NSURLIsExcludedFromBackupKey=@YES on Application Support/<bundleIdentifier>/RCTAsyncLocalStorage_V1 (lines 37-57, 137-150); thus Supabase session tokens in AsyncStorage are excluded from iOS backups by default. Storing session tokens in sandboxed, Data-Protection-encrypted, backup-excluded AsyncStorage rather than Keychain without an unprivileged local or backup access path is defense-in-depth hardening without a boundary crossing. Separately, expo-secure-store ~58.0.3 (node_modules/expo-secure-store/ios/SecureStoreModule.swift:194-225) defaults omitted keychainAccessible to kSecAttrAccessibleWhenUnlocked without kSecAttrSynchronizable, so arshif.backup.key in src/features/backup/service.ts:25 is excluded from unencrypted backups and iCloud Keychain sync and only migrates in the device owner's encrypted backups/restores, which aligns with its recovery-key role and is unrelated to Supabase session backup exclusion.
